# Dashboard V2 Design

## Dashboard Philosophy

The dashboard is not intended to display every available metric.

Its purpose is to help a user decide whether they should rent hashpower, understand why that recommendation was made, and know exactly how to execute that recommendation.

Every section should answer a specific question, and every metric shown should help answer that question.

## Goal

The dashboard should answer one question within 10 seconds:

> Should I rent hashpower right now?

Everything on the page should support that decision.

---

# Section 1 — Decision

This is the first thing the user sees.

Display:

- Current Recommendation
- Opportunity Score
- Action
- Market Regime

Purpose:

Should I rent right now?

---

# Section 2 — Why

Explain why the recommendation was made.

Display:

- Fair Value Ratio
- Probability
- Risk Adjusted ROI
- Rental Premium

Purpose:

Why is the engine recommending this?

---

# Section 3 — Market

Explain what the market is doing.

Display:

- Trend
- Momentum
- RSI
- ATR
- Technical Score

Below this, display a Technical Summary.

Purpose:

What is the market telling us?

---

# Section 4 — Recommended Strike

Display:

- Budget
- Hashrate
- Duration
- Expected Profit
- Probability

Purpose:

If I rent, what should I rent?

---

# Section 5 — Pool Routing

Display:

- Recommended Pool
- Routing Score
- Dominance
- Reason

Purpose:

Where should I point my hashrate?

---

2. Explanation second.
3. Technical evidence third.
